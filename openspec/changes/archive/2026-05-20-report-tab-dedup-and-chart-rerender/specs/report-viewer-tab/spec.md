## ADDED Requirements

### Requirement: Report viewer tab deduplication
When opening a report viewer tab, the system SHALL check whether a tab with the same `tabId` (`report-viewer:{reportId}`) already exists in `tabs[]`. If it exists, the system SHALL focus the existing tab. If it does not exist, the system SHALL create a new tab.

#### Scenario: Opening a report that already has a tab
- **WHEN** user clicks a report in the library or report card, and a `report_viewer` tab with `tabId = "report-viewer:{reportId}"` already exists in `tabs[]`
- **THEN** the system SHALL call `focusTab(existingTabId)` to bring the existing tab to the foreground; no new tab SHALL be created

#### Scenario: Opening a report for the first time
- **WHEN** user clicks a report and no `report_viewer` tab with matching `reportId` exists in `tabs[]`
- **THEN** the system SHALL create a new tab via `openTab()` with `tabId = "report-viewer:{reportId}"`

### Requirement: Report viewer iframe reloads on remount
The iframe in `ReportViewerTab` SHALL reload the full HTML content from the server every time the component mounts, bypassing browser cache.

#### Scenario: Tab closed and reopened
- **WHEN** a report viewer tab is closed (trashed) and the same report is reopened
- **THEN** the iframe SHALL issue a fresh HTTP request to the report HTML endpoint (not serve from cache)

### Requirement: Chart container fallback height
The HTML generated by `ReportRenderer` for each chart block SHALL include an inline `height` style on the chart container `<div>` as a fallback when CSS has not yet loaded.

#### Scenario: ECharts initializes before CSS loads
- **WHEN** the report HTML loads in an iframe and the inline bootstrap script executes before `ledger.css` has been applied
- **THEN** each chart container `<div data-ledger-chart-id="...">` SHALL have a non-zero height via inline `style`, allowing ECharts to render with visible dimensions
