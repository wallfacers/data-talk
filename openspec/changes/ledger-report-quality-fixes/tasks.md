## 2. ReportSchemaValidator collect-all 改造

- [x] 2.1 新建 `server/data-talk-application/src/main/java/com/datatalk/application/report/Violation.java`：record `{String code, String path, String message}`
- [x] 2.2 修改 `ReportSchemaValidator.validate(JsonNode)` 签名为 `List<Violation> validate(JsonNode)`：所有原 `throw fail(...)` 改为 `violations.add(new Violation(...))`，最后返回；为每条违规填 `path`（顶层错用 `""`，section/block 错按 `sections[idx]` / `sections[idx].blocks[idx]` / `appendix[idx]` 拼接）

- [x] 2.5 修改 `ReportArtifactService.promote`：调用 validator 后若 violations 非空 → `throw new ReportValidationException(violations)`，外层 try-catch 路径不变
- [x] 2.6 修改 `server/data-talk-adapter/src/main/java/com/datatalk/adapter/actions/PromoteReportActionHandler.java`：catch `ReportValidationException` 时返回 `{ error, errorCode, errorCodes, violations, recoveryHints }`；保留 `errorCode = errorCodes[0]` 兼容；`outputSchema` 增加 `errorCodes` / `violations` / `recoveryHints` 字段说明（仅文档性，不强制 enforce）

## 3. ReportRenderer TOC + cover sanitize

- [x] 3.1 在 `ReportRenderer` 新增 `static final Pattern AUTHOR_WATERMARK_PATTERN`（不区分大小写）：`^(datatalk[\s·-]?(自动生成|生成|auto[\s-]?generated)|auto[\s-]?generated|ai\s?生成|自动生成|系统生成|generated\s+by\s+.*)$`；新增 `static String sanitizeAuthor(String)` 工具方法（trim → 匹配 → 返回 "" 或原值，命中时 `log.warn`）
- [x] 3.2 修改 `ReportRenderer.renderCover`：拼 meta 行前调用 `sanitizeAuthor(b.path("author").asText(""))`
- [x] 3.3 修改 `ReportRenderer.toHtml`：渲染前调用新增私有方法 `collectChapters(JsonNode sections)` 返回 `List<ChapterInfo {int idx, String heading}>`；把 `chapters` 传入 `renderToc` 与 `renderChapter`
- [x] 3.4 修改 `ReportRenderer.renderToc(JsonNode b, List<ChapterInfo> chapters, StringBuilder out)`：输出 `<section class="ledger-toc"><h2>目录</h2><ol>...<li><a href="#chap-{idx}">{escapeHtml(heading)}</a></li>...</ol></section>`；chapters 为空时仍输出空 `<ol></ol>`
- [x] 3.5 修改 `ReportRenderer.renderChapter(JsonNode b, int idx, StringBuilder out)`：`<section>` 标签加 `id="chap-{idx}"`；调用方按预扫描时的 idx 顺序传入
