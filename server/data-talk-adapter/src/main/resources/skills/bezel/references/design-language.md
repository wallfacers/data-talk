# Bezel Design Language v2 — Style Matrix System

> Authoritative base-layer design-token specification for all Bezel dashboards.
> Every dashboard generated by the bezel skill MUST reference this file for
> color naming conventions, typography, spacing, ECharts baseline, and the
> token application mechanism.
>
> Visual personality (card shape, layout, motion, background) is defined in
> per-style files under `references/styles/`. Color overrides are defined in
> per-industry files under `references/industries/`. This document supplies
> the base layer that styles and industries build upon.

## 1. Architecture Overview

The Bezel design system uses a **style matrix** that decouples **industry** (data
semantics, KPI definitions, color palette) from **visual style** (layout,
card shape, KPI form, motion, background atmosphere).

### 1.1 The 6 Visual Styles

Six distinct visual personalities are defined in `references/styles/`:

| Style       | File                    | Philosophy                                        |
|-------------|-------------------------|---------------------------------------------------|
| Orbital     | `styles/orbital.md`     | Circles, arcs, rings; center-radiating layout     |
| Mosaic      | `styles/mosaic.md`      | Bento grid; maximum information density           |
| Horizon     | `styles/horizon.md`     | Horizontal strata; top-to-bottom strategy-to-detail|
| Organic     | `styles/organic.md`     | Warm, breathing; people-centered, generous space  |
| Monument    | `styles/monument.md`    | Symmetry, fine lines, authority, precision        |
| Terrain     | `styles/terrain.md`     | Natural forms, earth tones, spatial/geographic    |

Each style file contains its own complete set of design tokens: layout
skeleton, card shape, KPI form, chart configuration, background
implementation, and motion patterns.

### 1.2 Token Cascade

Tokens are applied in three layers. Later declarations override earlier ones
via the standard CSS cascade:

```
base (this file)  -->  style  -->  industry
spacing, typography   card shape,   accent colors,
naming conventions    layout,       bg-app overrides
                      motion,
                      background
```

1. **Base tokens** (design-language.md): spacing scale, typography, CSS
   variable naming conventions, ECharts structural baseline.
2. **Style tokens** (references/styles/\<style\>.md): card radius, border,
   shadow, blur, hover behavior, layout technique, ambient motion, background
   atmosphere, chart type recommendations.
3. **Industry color overrides** (references/industries/\<industry\>.md):
   `--bezel-accent-primary`, `--bezel-accent-secondary`, `--bezel-bg-app`,
   and derived token values.

## 2. Base Token Naming Convention

All dashboard stylesheets declare color tokens as CSS custom properties on
`:root`. The canonical variable names are:

| Token                        | Purpose                                      |
|------------------------------|----------------------------------------------|
| `--bezel-bg-app`             | Full-page body background                    |
| `--bezel-bg-panel`           | Semi-transparent panel / topbar / sidebar    |
| `--bezel-bg-card`            | Card surface (glass layer)                   |
| `--bezel-text-strong`        | High-emphasis text: titles, hero KPI values  |
| `--bezel-text-base`          | Primary body text                            |
| `--bezel-text-muted`         | Secondary / helper labels, axis text         |
| `--bezel-accent-primary`     | Brand accent: card-title bar, primary charts |
| `--bezel-accent-secondary`   | Supporting accent: gradients, secondary data |
| `--bezel-accent-warn`        | Warning state (amber/orange range)          |
| `--bezel-accent-success`     | Positive state (green range)                 |
| `--bezel-accent-danger`      | Alert / error state (red range)              |
| `--bezel-grid-line`          | Subtle chart grid line                       |
| `--bezel-grid-line-strong`   | Emphasized grid line or border               |

Style files may introduce additional style-specific tokens (e.g.
`--card-radius`, `--card-bg` opacity, `--motion-duration`, `--motion-easing`)
that are not defined in this base layer.

## 3. Default Neutral Values

When no industry override is specified, use this neutral dark palette:

```css
:root {
  --bezel-bg-app:           #0a0e1a;
  --bezel-bg-panel:         rgba(10, 18, 36, 0.60);
  --bezel-bg-card:          rgba(15, 23, 42, 0.55);
  --bezel-text-strong:      #e2e8f0;
  --bezel-text-base:        #cbd5e1;
  --bezel-text-muted:       #64748b;
  --bezel-accent-primary:   #00d4ff;
  --bezel-accent-secondary: #14b8a6;
  --bezel-accent-warn:      #f59e0b;
  --bezel-accent-success:   #10b981;
  --bezel-accent-danger:    #ef4444;
  --bezel-grid-line:        rgba(148, 163, 184, 0.08);
  --bezel-grid-line-strong: rgba(148, 163, 184, 0.20);
}
```

### Accent-Derived Semantics

For each industry, derive state colors from the accent palette unless the
industry explicitly overrides:

| Token                    | Rule |
|--------------------------|------|
| `--bezel-accent-success` | Use `--bezel-accent-secondary` if it is a green tone; otherwise `#10b981` |
| `--bezel-accent-danger`  | Use `--bezel-accent-primary` if it is a red tone; otherwise `#ef4444` |
| `--bezel-accent-warn`    | Use `--bezel-accent-primary` if it is orange/amber; otherwise `#f59e0b` |

### Card Surface Convention

For every industry, the `--bezel-bg-card` is constructed as:

```css
--bezel-bg-card: rgba(R, G, B, 0.55);
```

where `R, G, B` are derived by lightening `--bezel-bg-app` by approximately
30%. The panel (`--bezel-bg-panel`) uses the same RGB at `0.60` opacity. Card
borders use the primary accent at low opacity:

```css
border: 1px solid rgba(var(--accent-primary-rgb), 0.18);
```

Each industry template should pre-compute and inline these values.

## 4. Spacing Scale

The spacing scale is a fixed set of values. Use multiples and combinations
only from this palette:

| Token Name   | Value  | Usage                                |
|-------------|--------|--------------------------------------|
| `--sp-1`    | 4 px   | Tight internal gap, icon-to-label    |
| `--sp-2`    | 8 px   | Card title margin-bottom             |
| `--sp-3`    | 12 px  | Dashboard grid gap, section padding  |
| `--sp-3.5`  | 14 px  | Card padding (horizontal), row gap   |
| `--sp-4`    | 16 px  | Column gap, section margin           |
| `--sp-6`    | 24 px  | Header padding, KPI row gap          |
| `--sp-8`    | 32 px  | Major section separation             |

### Common Layout Values

| Element        | Padding           | Gap               |
|---------------|-------------------|-------------------|
| Dashboard     | `12px -- 16px`    | `12px -- 16px`    |
| Card          | `12px 14px`       | internal: `8px`   |
| Topbar        | `0 24px`          | `16px` (KPI pill) |
| KPI Pill      | `0 18px`          | `2px -- 6px`      |
| Main Content  | `16px 16px 0`     | `14px -- 16px`    |

## 5. Typography

### 5.1 Font Stack

```css
font-family: 'PingFang SC', 'Microsoft YaHei', sans-serif;
```

Exception: **Cybersecurity** uses `'Courier New', Courier, monospace` for a
terminal aesthetic. The Monument style may specify a serif font via CDN
(Noto Serif SC) with `'PingFang SC', 'Microsoft YaHei', serif` as fallback.

### 5.2 Type Scale

| Role          | Font Size    | Weight | Letter Spacing        | Additional                           |
|---------------|-------------|--------|-----------------------|--------------------------------------|
| Page Title    | 22 -- 28 px | 700    | 2 -- 8 px             | Gradient text or accent color        |
| KPI Numbers   | 24 -- 48 px | 700    | 1 -- 2 px             | `font-variant-numeric: tabular-nums` |
| KPI Labels    | 11 -- 12 px | 400    | 1 px                  | `color: var(--bezel-text-muted)`     |
| Card Title    | 13 -- 14 px | 700    | 1 -- 2 px             | Accent color                         |
| Card Body     | 11 -- 12 px | 400    | 0                     | `color: var(--bezel-text-base)`      |
| Trend / Badge | 11 px       | 600    | 0                     | `font-variant-numeric: tabular-nums` |
| Clock         | 13 -- 15 px | 600    | 1 -- 2 px             | `font-variant-numeric: tabular-nums` |
| Subtitle      | 11 -- 12 px | 400    | 2 -- 4 px, uppercase  | `color: var(--bezel-text-muted)`     |
| Chart Axis    | 9 -- 11 px  | 400    | 0                     | `color: var(--bezel-text-muted)`     |

### 5.3 Tabular Numeric Alignment

All numeric displays (KPI values, trend percentages, counters, clocks) MUST
use:

```css
font-variant-numeric: tabular-nums;
```

This ensures equal-width digit rendering so numbers do not shift during live
updates.

## 7. ECharts Theme Baseline

All ECharts instances share a common dark theme structural baseline. Visual
style files customize chart types and rendering details (bar gradients, area
fills, gauge angles, pie configurations), but inherit the configuration below.

### 7.1 Common ECharts Variables

These values represent the standard baseline shared across all styles:

```javascript
const bezelEChartsBase = {
  // Global
  backgroundColor: 'transparent',
  textStyle: {
    fontFamily: "'PingFang SC', 'Microsoft YaHei', sans-serif"
  },

  // Title
  title: {
    textStyle: {
      color: '#e2e8f0',
      fontSize: 14,
      fontWeight: 700
    }
  },

  // Legend
  legend: {
    textStyle: {
      color: '#94a3b8',
      fontSize: 11
    },
    top: 0,
    right: 8
  },

  // Tooltip (darkTooltip)
  tooltip: {
    backgroundColor: 'rgba(10, 18, 36, 0.92)',
    borderColor: 'rgba(0, 212, 255, 0.3)',
    textStyle: {
      color: '#e2e8f0',
      fontSize: 12
    },
    padding: [8, 12]
  },

  // Category Axis (darkAxis)
  categoryAxis: {
    axisLine: {
      lineStyle: { color: 'rgba(148, 163, 184, 0.20)' }
    },
    axisLabel: {
      color: '#64748b',
      fontSize: 10
    },
    axisTick: { show: false },
    splitLine: { show: false }
  },

  // Value Axis
  valueAxis: {
    axisLine: { show: false },
    axisLabel: {
      color: '#64748b',
      fontSize: 10
    },
    axisTick: { show: false },
    splitLine: {
      lineStyle: {
        type: 'dashed',
        color: 'rgba(148, 163, 184, 0.08)'
      }
    }
  },

  // Grid (darkGrid)
  grid: {
    left: 48,
    right: 20,
    top: 32,
    bottom: 24,
    containLabel: false
  }
};
```

### 7.2 Tooltip Configuration (darkTooltip)

The tooltip uses a semi-transparent dark background with accent-colored
border. For each industry, pass the RGB components of
`--bezel-accent-primary`:

```javascript
function createTooltip(accentRGB, overrides) {
  return {
    backgroundColor: 'rgba(10, 18, 36, 0.92)',
    borderColor: `rgba(${accentRGB}, 0.45)`,
    textStyle: { color: '#e2e8f0', fontSize: 12 },
    padding: [8, 12],
    ...overrides
  };
}
```

### 7.3 Grid Line Configuration (darkGrid)

The grid lines use a consistent subtle dashed pattern:

```javascript
const darkGrid = {
  borderColor: 'rgba(148, 163, 184, 0.12)',
  lineStyle: {
    type: 'dashed',
    color: 'rgba(148, 163, 184, 0.15)'
  }
};
```

Apply `darkGrid.lineStyle` to `splitLine` on value axes:

```javascript
yAxis: {
  splitLine: darkGrid.lineStyle
}
```

### 7.4 Resizing

All ECharts instances MUST be registered for resize:

```javascript
const charts = [];
// ... after each echarts.init() and setOption() ...
charts.push(chartInstance);

window.addEventListener('resize', () => {
  charts.forEach(c => c.resize());
});
```

### 7.5 Style-Specific Chart Configuration

Industry color palettes, gradient bar patterns, area fill patterns, heatmap
visual maps, gauge configurations, and pie/donut configurations are now
defined in the individual style files (`references/styles/<style>.md`). Each
style specifies its recommended chart types, rendering options, and complete
ECharts option templates.

## 8. Accessibility

All dashboards generated by the Bezel system must meet these accessibility
requirements regardless of style:

### 8.1 Color Contrast

- All body text must meet **WCAG AA 4.5:1** contrast ratio against the card
  background.
- Large text (18px+ or 14px+ bold) must meet **WCAG AA 3:1** contrast ratio.
- This is especially important for Organic (low background opacity + blur) and
  Mosaic (high background opacity, potentially low contrast for muted labels).
  Each style file must specify minimum text colors that achieve this.

### 8.2 Reduced Motion

- `prefers-reduced-motion` MUST suppress all animations in every style.
- All ambient animations and hover transitions must be wrapped in a
  `@media (prefers-reduced-motion: no-preference)` query.
- When the user prefers reduced motion, only instant state changes remain.
- This applies universally across all 6 visual styles.

### 8.3 Font Fallback

- Font fallback chains must include system fonts.
- The default stack is `'PingFang SC', 'Microsoft YaHei', sans-serif`.
- Monument's serif font must include
  `'PingFang SC', 'Microsoft YaHei', serif` as fallback.
- Cybersecurity's monospace stack is
  `'Courier New', Courier, monospace`.

## 9. Token Application Mechanism

Compiled HTML embeds CSS in three sequential layers. Because each layer
declares tokens on `:root`, the standard CSS cascade ensures that later
declarations override earlier ones.

### 9.1 Layer 1 — Base Tokens (from this file)

Spacing scale, typography, and naming conventions. These are the same for
every dashboard regardless of style or industry.

```css
:root {
  /* Spacing */
  --sp-1: 4px;
  --sp-2: 8px;
  --sp-3: 12px;
  --sp-3.5: 14px;
  --sp-4: 16px;
  --sp-6: 24px;
  --sp-8: 32px;

  /* Neutral color defaults (overridden by layers 2 and 3) */
  --bezel-bg-app:           #0a0e1a;
  --bezel-bg-panel:         rgba(10, 18, 36, 0.60);
  --bezel-bg-card:          rgba(15, 23, 42, 0.55);
  --bezel-text-strong:      #e2e8f0;
  --bezel-text-base:        #cbd5e1;
  --bezel-text-muted:       #64748b;
  --bezel-accent-primary:   #00d4ff;
  --bezel-accent-secondary: #14b8a6;
  --bezel-accent-warn:      #f59e0b;
  --bezel-accent-success:   #10b981;
  --bezel-accent-danger:    #ef4444;
  --bezel-grid-line:        rgba(148, 163, 184, 0.08);
  --bezel-grid-line-strong: rgba(148, 163, 184, 0.20);
}
```

### 9.2 Layer 2 — Style Tokens (from references/styles/\<style\>.md)

The style file provides its complete `:root` block containing card shape,
layout, motion, and background tokens. This layer re-declares any base tokens
that the style overrides (e.g., `--bezel-bg-card` opacity, `--bezel-radius-card`).

Example: reading `references/styles/mosaic.md` extracts the Mosaic style's
`:root` block with its 4px card radius, 0.85 background opacity, 150ms motion
duration, and solid background (no blur).

### 9.3 Layer 3 — Industry Color Overrides (from references/industries/\<industry\>.md)

The industry file provides a minimal `:root` block that overrides color tokens
only: `--bezel-accent-primary`, `--bezel-accent-secondary`, `--bezel-bg-app`,
and derived values (`--bezel-bg-card`, `--bezel-bg-panel`, border colors).

Example: reading `references/industries/ecommerce.md` extracts overrides for
red accent, gold secondary accent, and warm dark brown background.

### 9.4 Merge Order Summary

```
<html>
  <head>
    <style>
      /* Layer 1: Base — spacing, typography, neutral defaults */
      :root { ... }

      /* Layer 2: Style — card shape, layout, motion, background */
      :root { ... }

      /* Layer 3: Industry — color overrides */
      :root { ... }
    </style>
  </head>
  ...
</html>
```

Later `:root` declarations override earlier ones via CSS cascade. The compile
process in `compile-rules.md` (STEP 3) performs this merge automatically by
reading the base file, resolving the style from the mapping table, and
extracting the industry color overrides.
