# 12 行业场景大屏独立精品化重设计

## 1. 项目概述

**目标**：对 `tmp/Dashboard/` 下 12 个行业场景大屏 HTML 报表进行全维度独立精品化升级。

**范围**：12 个独立 HTML 文件，纯前端（HTML + CSS + ECharts 5.5），无后端依赖。

**设计策略**：每个行业大屏完全独立设计——不追求统一骨架，而是根据行业属性选择截然不同的美学方向、布局范式和数据叙事方式。从现有 4-6 个图表提升至 8-10 个，数据注入真实业务波动与故事性。

---

## 2. 设计方法论

### 2.1 三维度升级矩阵

| 维度 | 升级前 | 升级后 |
|------|--------|--------|
| **视觉** | 暗色主题 + 通用卡片 | 行业专属美学（色调/质感/动效/字体） |
| **数据** | 4-6 个基础图表，静态模拟数据 | 8-10 个图表，带趋势/异常/对比的真实业务数据 |
| **交互** | 基础 hover tooltip | 入场动画、数字滚动、告警跑马灯、实时时钟、呼吸灯 |

### 2.2 每屏设计公式

```
行业大屏 = 行业美学 DNA（色调+质感+字体）
        + 核心布局范式（地图/拓扑/仪表盘/漏斗 等）
        + 8-10 个图表（覆盖 5W2H 数据维度）
        + 3 层数据叙事（KPI 总览 → 趋势分析 → 细节洞察）
        + 实时感营造（时钟 + 跑马灯 + 动态数据）
```

### 2.3 数据真实性策略

所有模拟数据遵循以下规则：
- **带波动**：时间序列数据含工作日/周末周期、季节性波动
- **有异常**：刻意植入 1-2 个业务异常点（如电商大促峰值、制造设备故障）
- **可对比**：同比/环比指标、目标达成率、行业基准线
- **有故事**：数据背后隐含业务叙事（如"Q3 新客获客成本上升 15%，但 LTV 同步提升 22%"）

## 3. 12 行业独立设计方案

### 3.1 企业级数据大屏监控系统（01-multi-screen-dashboard）

**行业 DNA**：指挥中心 / 科幻 / 全局掌控

**美学方向**：
- 色调：深邃宇宙蓝黑 `#060b14` + 霓虹青蓝 `#00d4ff` + 数据绿 `#10e873`
- 质感：网格背景 + 粒子上升 + 顶部径向光晕
- 字体：标题用宽体科技感（`Helvetica Neue` 字重 900），数据用等宽字体

**布局范式**：中央场景切换轮盘
- 中央：12 个行业缩略图轮盘（或 3x4 网格），当前选中高亮
- 顶部：系统级 KPI 带（总数据量、API QPS、服务健康度、在线用户数）
- 底部：实时告警事件时间轴

**数据增强（新增）**：
- 跨行业数据对比雷达图（各场景活跃度、数据量、告警数）
- 系统资源监控仪表盘（CPU/内存/网络实时使用率）
- 24h 服务可用性热力图
- API 响应时间 P50/P95/P99 分布

## 4. 共同技术升级规范

### 4.1 视觉层统一规范

| 元素 | 规范 |
|------|------|
| **背景** | 每个大屏必须有一个动态背景（粒子/网格/波浪/数字雨/光晕等） |
| **卡片** | 行业专属卡片样式（边框/圆角/阴影/毛玻璃），禁止通用白边卡片 |
| **字体** | 标题字号 ≥ 20px，字重 ≥ 700；数据数字用 tabular-nums；等宽字体用于终端风 |
| **色彩** | 每个大屏定义 1 个主色 + 2-3 个辅助色，禁止直接拷贝其他大屏色值 |
| **间距** | 遵循 8px 网格，模块间距 10-16px，大屏边距 16-24px |

### 4.2 交互层统一规范

| 元素 | 规范 |
|------|------|
| **入场动画** | 页面加载时 KPI 数字从 0 滚动到目标值，图表 stagger 入场（delay 50-100ms） |
| **数字滚动** | 所有 KPI 数字使用 `requestAnimationFrame` 实现平滑滚动，持续 1-1.5s |
| **hover 反馈** | 卡片 hover 微放大（scale 1.02）+ 边框高亮 |
| **实时时钟** | 每个大屏右上角显示实时时间，格式 `YYYY-MM-DD HH:mm:ss`，每秒更新 |
| **跑马灯** | 底部告警/事件跑马灯，无缝循环滚动，速度 20-30s 一轮 |

### 4.4 数据真实性规范

| 规则 | 说明 |
|------|------|
| **时间序列** | 必须包含 7-12 个数据点，带周期波动（工作日高、周末低） |
| **异常点** | 至少 1 个明显异常点（峰值/谷值），并在 tooltip 中可识别 |
| **对比维度** | 至少 1 个图表包含同比/环比/目标对比 |
| **层级关系** | 树图/旭日图数据需有 2-3 层 drill-down 结构 |
| **地理数据** | 地图类图表使用真实省份/城市名称，数据值符合该地经济特征 |

## 5. 文件输出规范

- **输出位置**：直接覆盖 `tmp/Dashboard/` 下对应 HTML 文件
- **技术栈**：纯 HTML5 + 内联 CSS + ECharts 5.5 CDN（`https://cdn.jsdelivr.net/npm/echarts@5.5.0/dist/echarts.min.js`）
- **兼容性**：Chrome/Edge/Firefox/Safari 最新 2 个主版本
- **性能**：首屏加载 ≤ 3s（ECharts 异步渲染），动画帧率 ≥ 30fps
- **响应式**：`1920x1080` 优先，`1366x768` 可用，`2560x1440` 扩展

## 6. 实施批次建议

按行业关联度和设计复杂度分 3 批实施：

| 批次 | 行业 | 理由 |
|------|------|------|
| **Batch 1** | 电商、制造、网络安全、金融 | 视觉风格差异大，可并行确立各方向标杆 |
| **Batch 2** | SaaS、物流、能源、医疗 | 复杂度中等，参考 Batch 1 经验 |
| **Batch 3** | HR、农业、教育、多屏总控 | 相对简单，最后收尾统一调优 |

## 7. Out of Scope

- 不引入 React/Vue 等框架，保持纯 HTML
- 不接入真实后端数据源，保持前端模拟数据
- 不做 3D 图表（性能/复杂度权衡）
- 不做移动端适配（大屏默认横屏 16:9）
- 不引入额外图表库（仅 ECharts 5.5）
