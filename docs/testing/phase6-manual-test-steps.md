# Phase 6 手动测试步骤文档

## 测试前准备

### 启动服务
```bash
# 1. 启动后端 (端口 8080)
cd server && mvn spring-boot:run -pl data-talk-adapter

# 2. 启动 OpenCode AI 服务 (按项目配置启动)

# 3. 启动前端 Tauri 应用
cd client && npm run tauri dev
```

### 测试账号准备
- 确保已配置数据源连接（MySQL/PostgreSQL/H2）
- 保已在设置中配置 AI 模型提供商

## 场景 1: 切走再切回不丢 AI 消息

### 目的
验证 Sidebar 切换会话后，对话区消息完整重现

### 触发步骤
1. **创建会话 A**: 点击侧边栏顶部「+ 创建会话」按钮
2. **发送消息**: 在 composer 输入 `查询所有用户表`，点击发送按钮（或按 Enter）
3. **等待 AI 响应完成**: 观察 AI 返回完整的消息（包含 part 卡片）
4. **创建会话 B**: 再次点击「+ 创建会话」按钮
5. **切回会话 A**: 在侧边栏点击刚才的会话 A（第一条会话）

### 预期结果
- 会话 A 的对话区完整显示之前的用户消息 + AI 响应
- 所有 part 卡片（工具调用、SQL 代码块、Artifact 等）都正常渲染
- 无空白、无重复、无报错

4. **点击会话进入**: 点击刷新前的会话

### 预期结果

- 进入会话后，所有消息完整显示
- 消息顺序正确，无丢失

- 发送消息后，显示服务不可用错误提示
- 恢复 OpenCode 后，提示消失，功能恢复

## 场景 16: 未知 part type 占位

### 目的
验证未知 part type 的容错显示

### 触发方式（需后端配合）
需要后端返回一个前端未定义的 part type，例如：

```json
{
  "type": "unknown_new_type",
  "content": "这是一个未知类型的 part"
}
```

### 方法 A: 修改后端 mock（开发环境）
1. 在后端某个 ActionHandler 中临时返回未知 part type
2. 发送触发该 Action 的消息

### 方法 B: 使用 WireMock/FakeOpenCodeServer
1. 配置 FakeOpenCodeServer 返回包含未知 part type 的响应
2. 发送消息触发

### 预期结果
- **不白屏、不崩溃**
- 显示「UnknownPart」黄色占位卡片
- 卡片提示 "未知消息类型: unknown_new_type"
- 其他正常消息不受影响
